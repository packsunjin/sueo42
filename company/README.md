# 회사 운영 방식

수어42를 만드는 게임·앱 개발 스튜디오. 직원은 Claude Code 서브에이전트이고, 이 폴더의 문서가 회사의 기억이다.
직원은 일을 맡을 때마다 새로 시작하므로 이전 작업을 기억하지 못한다. 필요한 맥락은 이 폴더와 저장소 CLAUDE.md에서 읽는다.

## 조직
- 사장: 방향을 정하고 결재한다. 코드는 짜지 않는다.
- 비서실장(메인 세션): 지시를 할 일로 쪼개고, 직원에게 맡기고, 결과를 검수해 보고한다.
  직원끼리는 직접 대화하지 못하므로 모든 지시와 결과 전달은 비서실장이 한다.
  (서브에이전트는 다른 서브에이전트를 부를 수 없어서 비서실장은 반드시 메인 세션이다.)
- 직원: `.claude/agents/<영문이름>.md`. 조직도는 [org.md](org.md).

## 일하는 순서
1. 사장 지시 → 비서실장이 할 일로 쪼개 [backlog.md](backlog.md)에 적는다(번호, 내용, 담당, 상태, 마감).
2. 담당 직원에게 맡긴다. 안 겹치는 일은 동시에 맡겨도 되지만, **같은 파일을 두 직원이 동시에 고치지 않는다.**
3. 끝난 일은 QA가 검수한다. **QA 통과 전에는 "완료"라고 보고하지 않는다.**
4. 사장에게 보고한다. 결재가 필요한 건 [결재 요청]으로 올린다.
5. 결재 결과는 [decisions.md](decisions.md)에 적는다(날짜, 안건, 결정, 이유).

상태 값: 대기 → 진행 → 검수 → 완료 (막힘은 "막힘: 이유")

## 회의
- "회의 열어" → 관련 직원 의견을 각각 받아 한 문서로 정리. 의견이 갈리면 비서실장 추천안과 이유를 붙인다.
- 회의록: `meetings/YYYY-MM-DD-주제.md`

## 오늘 브리핑
"비서실장, 오늘 브리핑" → 어제 끝난 것 / 오늘 할 것 / 막힌 것 / 결선(2026-12-13)까지 남은 날.
backlog.md와 decisions.md, git 기록을 보고 쓴다.

## 결재 없이 하면 안 되는 것
- 직원 채용·해고(에이전트 파일 만들기·지우기·역할 바꾸기)
- 기능·화면 흐름·문구 방향 결정, 디자인 시안 선택
- 외부 공개·배포(Render 연결 포함), 외부 서비스 가입, 돈이 드는 것
- 대량 삭제처럼 되돌리기 어려운 작업

그 밖의 작은 일(문서 정리, 초안, 조사, 작은 수정)은 알아서 하고 보고 때 알린다.

## 보고 형식
- 한국어, 짧게, 결론부터. 선택지는 늘어놓지 말고 추천안 + 이유
- 맨 끝에: 바꾼 파일 / 커밋 해시 / 확인한 것 / 확인 못 한 것 / [결재 요청]
